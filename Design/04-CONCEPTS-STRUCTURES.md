## Диагноз: почему волны 1—2 не зацепили

Обратная связь была: «хорошие идеи, но ничего не зацепило, хочется чтобы дизайны сильнее различались».

Разбор показал причину. **Все десять концепций имели один и тот же скелет:**

```
шапка → блок нагрузки → список задач → нижняя навигация
```

Менялись палитра, радиусы, гарнитура, подпись формы, параметры пружин. Не менялось **то, как устроена информация на экране.**

Мозг считывает силуэт раньше цвета — за первые ~300 мс. Поэтому десять разных костюмов на одном силуэте прочитались как один продукт. Это классическая ошибка: работа на уровне стиля вместо работы на уровне структуры.

### Новое правило волны 3

> **Скелет выбирается первым. Характер надевается вторым.**
> Концепция считается пройденной, только если её структуру можно узнать по чёрно-белому силуэту, без единого цвета.

Ни одна из девяти новых концепций не является списком с шапкой.

# 11 · ЦИФЕРБЛАТ · премиальность

**Скелет:** круг вместо списка.
**Характер:** часовое дело — гильоше, индексы, воронёная сталь.

День — окружность на 18 часов (6:00–24:00, 20° на час). Каждая задача — сектор на внешнем кольце, длина сектора равна длительности. Стрелка идёт по кругу весь день. **Свободное время видно как пустая дуга** — это то, чего не показывает ни один список.

Списка на главном экране нет: под циферблатом только текущая задача и три ближайшие, каждая с отрезком, повторяющим её сектор.

| | Тёмная · воронёная сталь | Светлая · серебряный циферблат |
|---|---|---|
| База | `#0C0E12` | `#E6E7EA` |
| Лицо | `#12151C` | `#F6F7F9` |
| Кольцо | `#1A1E26` | `#D2D5DC` |
| Сектор | `#8898B8` | `#5A6A88` |
| Текущий | `#D8DCE4` | `#2C3648` |
| Стрелка | `#C4584A` | `#A33D2F` |

**Гильоше:** `repeating-conic-gradient` шагом 1.4°, прозрачность 3%.
**Цифры:** Cormorant Garamond.
**Движение:** `damping 0.95`, `stiffness 1800` — механический тик, не скольжение.

**Что меняет в продукте:** задачам нужно время начала, а не только длительность. Новое поле — но оно превращает список дел в реальный план дня. Перегруз перестаёт быть числом и становится тем, что круг не замыкается.

**Риск:** круг плохо держит больше 8—10 задач — сектора становятся нечитаемо тонкими. Нужен порог, после которого мелочь сворачивается в один сектор «прочее».

# 12 · КАРТОТЕКА · премиальность

**Скелет:** стопка в глубину вместо ленты.
**Характер:** архивный ящик — перфорация, штамп, машинопись.

Впереди одна карта, полная: номер, все поля, дата заведения, штамп «СРОЧНО». За ней рёбра следующих карт, читаются только заголовки. Свайп влево кладёт карту обратно в ящик, вправо — подшивает в фонд. **Скролла нет вообще.**

| | Тёмная · табачное дерево | Светлая · светлый дуб |
|---|---|---|
| База | `#17120E` | `#D9CFBC` |
| Ящик | `#211A14` | `#EFE8DA` |
| Карта | `#E8E0CE` | `#FFFCF5` |
| Текст на карте | `#2A2018` | `#2A2018` |
| Латунь | `#9A7B4F` | `#A8834F` |
| Штемпель | `#C0392B` | `#C0392B` |

**Перспектива:** `1000px`, наклон `5°`.
**Типографика:** моноширинная на карте — машинописный бланк.
**Движение:** `damping 0.85`, `stiffness 800` — картотечный щелчок.

**Что меняет в продукте:** все поля задачи, которые сейчас спрятаны в форме редактирования, выходят на лицевую сторону. Ваша трёхосевая категоризация наконец видна целиком — проект, место и тип занимают своё поле в бланке, а не превращаются в мелкие чипы.

**Риск:** одна карта за раз означает, что обзора дня нет — нужен второй экран «опись». И карточная метафора требует, чтобы каждая задача была достойна бланка: «купить хлеб» в ней выглядит нелепо.

# 13 · КОРЕШКИ · премиальность

**Скелет:** горизонталь вместо вертикали.
**Характер:** полка переплётов — кожа, тиснение, том.

Задачи — книжные корешки на полке. **Ширина корешка = длительность** (минуты ÷ 2.2), **цвет переплёта = проект**, **тиснение = приоритет**. Текущая задача снята с полки и выдвинута вперёд. Названия набраны вертикально, снизу вверх — как на настоящих корешках.

Весь день виден одним взглядом как физический объём, а не как число минут.

| Переплёт | Проект |
|---|---|
| `#6E2230` бордо | Клиент |
| `#234034` тёмно-зелёный | Финансы |
| `#1F3050` синий | Личный бренд |
| `#4A3020` коричневый | Тело |
| `#6E5520` охра | Дом |
| `#C6A34E` золото | тиснение |

Светлая тема: переплёты осветляются (`#9C4055`, `#3E6B55`, `#3B5580`, `#7A5433`), тиснение становится кремовым `#F4E9CE`, фон — пергамент `#EAE3D2`.

**Движение:** `damping 0.80`, `stiffness 550`.

**Что меняет в продукте:** длительность перестаёт быть цифрой и становится физическим размером. Перегруженный день — это полка, с которой корешки не помещаются. Поле `duration`, сейчас необязательное, становится смысловым центром.

**Риск:** короткие задачи получают корешок в 15—20 px, куда не влезает название. Правило: под 25 минут корешок безымянный, читается по цвету и по выдвижению. Плюс горизонтальный скролл на мобильном менее привычен.

# 14 · ПУЛЬТ · контроль

**Скелет:** сетка 2 × N вместо ленты.
**Характер:** приборная панель — гравированные таблички, тумблеры, винты.

Каждая задача — контур с гравированной табличкой, индикатором состояния и физическим тумблером. Выполнение — это **щелчок**, а не галочка. Читается не построчно, а как панель: взгляд охватывает всё поле сразу и выхватывает горящие индикаторы.

| | Тёмная · чёрный анодированный | Светлая · светлая панель |
|---|---|---|
| База | `#15171A` | `#DDE0E4` |
| Модуль | `#1D2024` | `#ECEEF0` |
| Табличка | `#2A2E33` | `#F9FAFB` |
| Ручка | `#C8CDD4` | `#FBFCFD` |
| Индикатор вкл | `#4FA86B` | `#2E7D4F` |
| Индикатор ждёт | `#D9922F` | `#A37020` |

**Фаска:** верх `rgba(255,255,255,0.10)`, низ `rgba(0,0,0,0.60)`.
**Движение:** `damping 1.00`, `stiffness 2200` — щелчок без отскока + `HapticFeedback`.

**Что меняет в продукте:** единственная концепция, где приложение ощущается через руку, а не только через глаз. Статусная модель «Стек ↔ Сегодня → Архив» ложится на три положения переключателя.

**Риск:** две колонки означают короткие названия — дисциплина в 32 символа. И скевоморфизм требует безупречного исполнения: плохо сделанный тумблер выглядит как игрушка 2011 года.

# 15 · ШЛЮЗ · контроль

**Скелет:** вертикальная воронка вместо списка.
**Характер:** промышленная пропускная система — бетон, разметка, штриховка.

Экран разделён на три зоны: **очередь → ворота → прошло**. Ширина ворот равна вашей норме в минутах. Всё, что не влезло, физически остаётся в воронке и помечено как затор.

Это единственная концепция, где перегруз — не красное число, а **видимая пробка**.

| | Тёмная · бетон | Светлая · светлый бетон |
|---|---|---|
| База | `#16181A` | `#DEDCD6` |
| Бетон | `#202325` | `#EAE8E2` |
| Разметка | `#D4B106` | `#9C8104` |
| Затор | `#B04A2E` | `#963B22` |
| Прошло | `#8FA88C` | `#4E6B4B` |

**Штриховка ворот:** `repeating-linear-gradient(45deg, разметка 0 6px, база 6px 12px)`.
**Радиусы:** 0 везде.
**Движение:** `damping 0.70`, `stiffness 700` — поток.

**Что меняет в продукте:** ваш overload-порог перестаёт быть настройкой в глубине меню и становится главным объектом экрана. Планирование — один жест: тащишь задачу в ворота, и видно, что вытесняется.

**Риск:** метафора давит. Каждое утро видеть затор из собственных дел честно, но тяжело. Нужен вариант, где очередь сворачивается. И промышленная эстетика противоположна премиальности — осознанный размен.

# 16 · ТРАЕКТОРИЯ · контроль

**Скелет:** график как главный экран.
**Характер:** прогноз.

Вместо «что делать» экран отвечает на вопрос **«когда день сломается»**. Кривая накопленной нагрузки по часам занимает половину экрана, задачи — узлы на ней, пунктир — норма. Точка пересечения названа по имени и по времени: «18:15 — Тренировка».

**Все остальные восемнадцать концепций показывают настоящее. Эта — единственная, которая показывает будущее.**

| | Тёмная | Светлая |
|---|---|---|
| База | `#0D1417` | `#EDF1F3` |
| Панель | `#131D22` | `#FFFFFF` |
| Кривая | `#4FA8D8` | `#1C7AA8` |
| Превышение | `#D4604A` | `#B03E29` |

**Ось X:** 6:00—24:00 · **Ось Y:** накопленные минуты · **Реализация:** Canvas / Path.
**Движение:** `damping 0.80`, `stiffness 1000`.

**Что меняет в продукте:** у вас уже есть всё для этой кривой — длительность каждой задачи и порог дня. Не хватает только времени начала. Это ближайший к текущему коду скелет и при этом самый непохожий на список. Ваш donut-календарь доказывает, что кастомная отрисовка в проекте освоена.

**Риск:** график — язык аналитика. Обязательна текстовая расшифровка под кривой. Без неё концепция не работает для половины аудитории 40–60.

# 17 · РАЗГРУЗКА · облегчение

**Скелет:** разрыв вместо списка.
**Опорное чувство:** облегчение. **Не премиальность и не контроль.**

Экран разорван надвое. Сверху — **пустая зона «в голове»**, и её пустота это не отсутствие контента, а главный результат. Снизу — плотное поле того, что уже вынесено наружу.

Большое число на экране — не «осталось 10», а **«выгружено 10»**. Главная кнопка не «Выполнить», а **«Выгрузить ещё»**.

### Почему это против жанра

Все таск-менеджеры устроены как счётчик долга: чем больше записал, тем больше должен. Поэтому люди перестают записывать. Здесь наоборот: чем больше выгрузил, тем спокойнее экран. Это единственная из девятнадцати концепций, которая **вознаграждает за запись**, а не за выполнение.

| | Светлая (основная) | Тёмная |
|---|---|---|
| База | `#EEF0EB` | `#141715` |
| Поверхность | `#FFFFFF` | `#1C201D` |
| Шалфей | `#6E9A7E` | `#8FB39B` |
| Текст | `#262B27` | `#E8EDE9` |

**Сигнальных цветов: ноль.** Красного нет вообще — подсветка срочности и есть источник тревоги. Приоритет живёт в порядке, а не в цвете.
**Вес шрифта:** 300 / 500. **Движение:** `damping 1.00`, `stiffness 200` — выдох.

**Что меняет в продукте:** алгоритм приоритета уходит с первого плана и работает молча. Это рискованно — ваше главное отличие становится невидимым. Зато барьер записи падает до нуля, а именно на нём умирают таск-менеджеры.

**Риск:** прямо противоречит заявленному ядру «контроль». Это не недостаток концепции, а развилка: либо продукт про власть над днём, либо про освобождение от него. **Совмещать эти два обещания в одном интерфейсе нельзя.**

# 18 · ПАРТИТУРА · поток

**Скелет:** нотный стан вместо ленты.
**Опорное чувство:** поток.

Каждый проект — своя строка, каждая задача — нота на временно́й оси: закрашенная для короткой, полая со штилем для средней, целая для длинной. Вертикальная черта — «сейчас».

### Что это даёт, чего нет у списка

Список не умеет показывать **паузы**. Партитура показывает: пустой участок стана — свободное время, скопление нот в одном месте — перегруз, пустая строка — заброшенный проект. Ваши три оси категоризации получают визуальный смысл: проект становится инструментом.

| | Тёмная · чёрная сцена | Светлая · нотная бумага |
|---|---|---|
| База | `#100E14` | `#F6F2EA` |
| Чернила | `#EDE9F2` | `#1A1620` |
| Стан | `#EDE9F2` @ 26% | `#1A1620` @ 34% |
| «Сейчас» | `#C06BB6` | `#9B3E94` |

**Цвет — один, и он обозначает только «сейчас».** Длительность кодируется формой ноты, а не оттенком — ровно как в настоящей нотации.
**Движение:** `damping 0.60`, `stiffness 420` — свинг.

**Что меняет в продукте:** планирование становится композицией — задачу двигают по стану, чтобы день зазвучал ровно. Перегруз превращается из ошибки в музыкальную проблему: слишком густо в одном такте. Мягче, чем «Шлюз», и так же честно.

**Риск:** метафора требует, чтобы человек знал, что такое нота. Нужна одноразовая подсказка. Больше 5 проектов на экран не помещается.

# 19 · ХРОНИКА · накопление

**Скелет:** годы вместо дня.
**Опорное чувство:** накопление и след.

Главный экран показывает не сегодня, а **всё вложенное время**. Строки — проекты, колонки — месяцы, плотность клетки — часы. Сегодняшний день — одна узкая колонка у правого края, обведённая рамкой.

Самое крупное число на экране — **412 часов за 14 месяцев**, а не 7 задач до вечера.

### Почему это отвечает на «великую цель»

Вы просили ощущение причастности к чему-то высшему. В волнах 1—2 я пытался дать его через обстановку — латунь, антикву, членский номер. Это декорация.

Здесь оно возникает из факта: человек видит, что 148 часов его жизни ушли в один конкретный проект. **Причастность — не оформление, а масштаб данных, который приложение решается показать.**

**Шкала плотности (тёмная):** `#241C15` → `#3A2B1D` → `#584022` → `#7E5A2C` → `#A56C36` → `#C88C4C`
**Шкала плотности (светлая):** `#E6DCCA` → `#D6C2A2` → `#C0A47C` → `#A8865A` → `#8A683C` → `#6E4E24`

**Матрица:** 6 проектов × 14 месяцев, клетка 16 × 15 px.
**Движение:** `damping 0.90`, `stiffness 600`.

**Что меняет в продукте:** архив перестаёт быть свалкой выполненного и становится главным активом. У вас уже есть `completed` с таймстампом и `duration` — этого почти хватает. Побочный эффект: удалять приложение становится жалко, потому что вместе с ним исчезает 412 часов истории.

**Риск:** у нового пользователя хроника пуста — первые два месяца экран выглядит как обещание, а не как ценность. Единственная концепция, которую по-настоящему можно оценить только через полгода.

# Рекомендация волны 3

**ЦИФЕРБЛАТ — если нужен премиум.** Единственная концепция, где премиальность и функция совпадают: часовое дело существует ради точного показа времени, а ваш продукт существует ради точного распределения времени. Круг даёт то, чего физически не может дать список — видимую пустоту между делами. Работает на обе возрастные группы.

**ТРАЕКТОРИЯ — если нужен контроль.** Ближайшая к текущему коду и при этом самая непохожая на список. Единственная, которая смотрит вперёд, а не отчитывается о настоящем. Всё, чего не хватает — время начала задачи.

**ХРОНИКА — если нужна причастность.** Отвечает на «великую цель» фактом, а не обстановкой. И сильнее всех работает на удержание: удалить приложение с 412 часами истории психологически трудно.

### Три вопроса, которые важнее выбора концепции

1. **Готовы ли вы добавить время начала задачи?** От этого зависят Циферблат, Траектория и Партитура — три из девяти.
2. **Контроль или облегчение?** Разгрузка (17) прямо противоречит контролю. Это стратегическая развилка продукта, а не вопрос оформления.
3. **Готовы ли вы, чтобы главный экран не был списком?** Все девять требуют этого. Если нет — нужно возвращаться к волнам 1—2 и признать, что различие будет только в стиле.
